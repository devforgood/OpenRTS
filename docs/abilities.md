# 능력(스킬) 시스템

영웅·근접·원거리 유닛이 쓰는 능력의 구조입니다. **AI(전투 봇)와 플레이어가 같은 엔진**을 씁니다. 차이는 누가 언제 쓸지 정하는 부분뿐입니다(AI: 데이터의 AI 힌트, 플레이어: Q W E R D F).

| 위치 | 내용 |
| --- | --- |
| `Shared/Runtime/Abilities/AbilityDefinition.cs` | 능력 데이터(`AbilityDefinition`), 목록과 종류별 보유(`AbilityCatalog`). 서버·클라이언트 공용 |
| `Server/.../Simulation/Abilities/AbilitySystem.cs` | 엔진: 시전 상태, 발동, 투사체·범위·돌진, 상태 효과, AI 사용 |
| `Server/.../Simulation/Abilities/AbilityTypes.cs` | 유닛별 상태(`AbilityState`, `ActiveCast`, `StatusInstance`), 스크립트(`IAbilityScript`, `AbilityScriptRegistry`) |
| `Client/Assets/Scripts/View/AbilityEffects.cs` | 연출 (투사체·범위 예고·폭발·적중) |
| `Client/Assets/Scripts/Controls/RtsInput.cs` | 단축키·대상 고르기 |

설계 출처: 참고 서버의 "데이터 + 스크립트, 시전 상태머신, 투사체/범위 판정" 구조만 참고하고 코드는 새로 작성했습니다(AGPL). 참고 서버 분석(`spells.md` 10장)에서 확인된 문제는 처음부터 피했습니다:

| 참고 서버 | 여기 |
| --- | --- |
| 피해량이 스크립트에 하드코딩 | 효과는 데이터(`AbilityEffect`). 스크립트는 값을 바꾸거나 덧붙이기만 |
| 정신 집중 콜백이 특정 조건에서만 등록, 선딜 0 이면 정신 집중 안 됨 | 정신 집중은 데이터(`ChannelTime`)만 보고, 선딜 0 이어도 시작 |
| 투사체가 벽을 통과, 빠르면 대상을 건너뜀 | 한 틱 이동 구간 전체를 훑어 맞히고(터널링 없음), 맵 벽·건물에 막힘 |
| 직선 투사체가 관통 수 제한을 무시 | `Pierce` 를 지킴 |
| 쿨감 부호 오류 등 | 쿨다운 감소는 아직 없음(추가할 때 `AbilityState.Cooldown` 한 곳에서) |

## 1. 데이터 (`AbilityDefinition`)

| 필드 | 뜻 |
| --- | --- |
| `Targeting` | `None`(자신·자기 주변), `Unit`(유닛 하나), `Point`(지점 — 직선 투사체·돌진은 방향) |
| `Delivery` | `Instant`, `Area`, `Projectile`, `Dash` (아래 3절) |
| `Range` | 시전 거리(가장자리 기준) / 직선 투사체 비행 거리 / 돌진 최대 거리 |
| `Cooldown`, `CastTime` | 재사용 대기, 선딜 |
| `ChannelTime`, `ChannelInterval` | 정신 집중 시간과 판정 주기 (Area 전용) |
| `Affects` | `Enemies` / `Allies` / `Self` 조합 |
| `Effect` | 맞을 때 효과: `Damage`, `Heal`, `Status`(+시간, 크기) |
| `AreaRadius`, `AreaDelay` | 범위 반지름, 예고 지연 |
| `ProjectileSpeed`, `ProjectileWidth`, `Pierce`, `Homing` | 투사체 |
| `DashSpeed` | 돌진 속도 (도착하면 `AreaRadius` 범위에 효과) |
| `SingleCaster` | 여러 유닛을 골라 쓰면 하나만(대상에 가장 가까운 준비된 유닛) / 모두 |
| `AiHint`, `AiMinCount`, `AiThreshold` | AI 가 언제 쓰는지 (5절) |

| Mend | 영웅 R | 없음 | 정신 집중 2초, 0.5초마다 범위 | 아군·자신 회복 15/회, 반지름 5, 쿨 25 |

## 2. 시전 흐름

```text
TryBegin (검증: 보유·준비·기절 아님·돌진 아님, 유닛 대상은 시전자 팀에 보이고 Affects 에 맞아야 함)
  └ 하던 건설 취소(환불)·공격 선딜 취소, 시전 전 명령 기억, Order = Cast
Approach   사거리 밖이면 걸어감 (유닛 대상, 지점 범위만. 직선 투사체·돌진은 바로 다음 단계). A* 예산 버전, 0.4초마다 재요청
Windup     선딜 동안 서 있음 → 발동. 재사용 대기는 이때 시작
Release    전달 방식별 (3절). 스크립트 OnRelease 가 false 면 여기서 끝
Channel    (정신 집중) 주기마다 자기 주변 범위 효과
Dash       (돌진) 도착하면 범위 효과
끝         시전 전 명령으로 복귀: 공격(대상 살아 있으면) / 공격 이동 / 이동 / 대기
```

취소: 기절, 사망, 대상이 죽거나 시야 밖으로 나감, 다른 명령(새 시전 포함). **발동 전에 취소되면 재사용 대기 없음**, 발동 후(정신 집중·돌진 중) 끊기면 재사용 대기는 그대로입니다.

틱 순서: `AbilitySystem.Update`(시전·정신 집중·지연 범위·상태 시간)는 전투 엔진·경제 다음, 이동 전. `UpdateAfterMovement`(돌진 도착, 투사체 명중)는 이동 뒤라 이번 틱 위치로 맞힙니다.

## 3. 전달 방식

| 방식 | 동작 |
| --- | --- |
| Instant | `Targeting=Unit` 이면 그 대상, 아니면 자신에게 즉시 |
| Area | 중심 = 지점(Point) / 대상 위치(Unit) / 자신(None). `AreaDelay > 0` 이면 예고 후 그때 범위 안에 있는 유닛만. `ChannelTime > 0` 이면 정신 집중 동안 자기 주변을 주기적으로 |
| Projectile (직선) | 지점 방향으로 `Range` 만큼. 매 틱 이동 구간 전체를 선분으로 훑어 폭 안의 대상을 앞에서부터 맞히고, `Pierce` 를 넘으면 그 자리에서 멈춤. 맵 벽과 맞힐 수 없는 건물·광맥에 막힘 |
| Projectile (유도) | `Homing` + 유닛 대상. 대상을 따라가 닿으면 맞힘, 대상이 죽으면 사라짐 |
| Dash | 사거리로 자르고, 벽에 막히면 막히기 직전까지. 돌진 중에는 ORCA 회피를 하지 않음(벽 밀어내기는 받음). 도착(또는 시간 초과)하면 자기 주변 범위 효과 |

범위 판정: 움직이는 유닛은 `중심 거리 ≤ 반지름 + r`, 건물은 발판까지 거리 ≤ 반지름. 광맥은 대상이 아닙니다. 중립 팀은 적도 아군도 아닙니다.

## 4. 효과와 상태

- 피해는 전투 엔진의 `ApplyDamage` 를 거칩니다 → 보호막 흡수, 도움 요청, 사망 이벤트가 평타와 같게 동작합니다.
- 회복은 최대 체력까지. 상태 효과는 건물에 걸리지 않습니다.

| 상태 | 효과 | 겹침 |
| --- | --- | --- |
| Stun | 이동 속도 0, 공격·시전·일 불가. 걸리면 하던 시전·돌진·공격 선딜·이동을 멈춤 | 같은 종류는 시간·크기 중 큰 쪽으로 갱신 |
| Slow | 이동 속도 × (1 − 크기), 가장 센 둔화 하나만 (최대 95%) | 갱신 |
| Shield | 크기만큼 피해를 먼저 흡수 | 따로 쌓임 |

이동 속도는 이제 유닛마다 `World.SpeedOf(u) = 설정 속도 × SpeedMultiplier` 입니다(선호 속도·ORCA·속도 제한 모두).

## 5. AI 사용

`BattleAi.Think` 가 판단할 때마다(0.25초) 먼저 `AbilitySystem.TryAiCast` 를 부릅니다. 준비된 능력을 보유 순서대로 보고, `AiHint` 조건이 맞는 첫 능력을 씁니다. **적은 시전자 팀에 보이는 유닛만** 봅니다.

| 힌트 | 조건 |
| --- | --- |
| `OnTarget` | 지금 싸우는 대상이 보이고 사거리 × 0.9 안 → 그 대상(위치)에게 |
| `EnemyCluster` | 범위 안에 보이는 적이 `AiMinCount` 이상. 자기 주변 능력은 자기 위치로, 지점 능력은 사거리 안 적 위치마다 주변 적 수를 세어 가장 많은 곳 |
| `SelfLowHealth` | 체력 비율 < `AiThreshold` 이고 싸우는 중 |
| `AlliesHurt` | 범위 안에 체력 비율 < `AiThreshold` 인 아군이 `AiMinCount` 이상 |
| `Never` | 쓰지 않음 |

플레이어 유닛은 자동으로 쓰지 않습니다(자동 시전은 이후 과제).

## 6. 스크립트 (`IAbilityScript`)

데이터로 표현하기 어려운 동작만 덧붙입니다. World 마다 등록부가 있습니다(`world.AbilitySystem.Scripts.Register(id, script)` — 테스트끼리 섞이지 않게 전역이 아님).

| 훅 | 시점 | 쓰임 |
| --- | --- | --- |
| `OnRelease(world, caster, cast)` | 발동 직전 | false → 발동 안 함(재사용 대기는 시작). 조건부 능력 |
| `ModifyEffect(world, caster, target, effect)` | 효과 적용 직전 | 대상에 따라 수치 변경 (예: 기절한 적에게 두 배) |
| `OnHit(world, caster, target, def)` | 효과 적용 뒤 | 추가 효과, 기록 |

예시는 `AbilityTests.DoubleOnStunned`. 서버 기본 스크립트를 넣으려면 `AbilitySystem` 생성자에서 등록하세요.

## 7. 네트워크

| 무엇 | 어떻게 | 공개 범위 |
| --- | --- | --- |
| 시전 명령 | `UnitCommand` `Cast`(=7) + `Ability`, `TargetUnit`/`Target`, `ClientTick`(선딜 지연 보상) | 서버가 소유권·보유·준비·대상(시야, 적/아군)을 다시 확인. 거부하면 그 능력을 가진 가장 가까운 유닛 이름으로 `CastCancel` |
| 상태 | 스냅샷 `UnitFlags`: Stunned 16, Casting 32, Slowed 64, Shielded 128 | 스냅샷 시야 필터를 따름 |
| 연출 | `AbilityEvents`(=12): CastStart, CastCancel, ProjectileLaunch/End, AreaTelegraph/Hit, DashStart, ChannelStart, Hit | 팀마다 시전자나 지점이 보일 때만, 안 보이는 시전자·대상 ID 는 0 |
| 재사용 대기 | `PlayerState` 의 `Cooldowns` (대기 중인 것만, 0.1초 단위) | 그 플레이어 유닛만, 그 플레이어에게만 |

형식은 [protocol.md](protocol.md).

## 8. 클라이언트

- **단축키**: 선택한 내 유닛들이 가진 능력을 영웅 먼저, 종류별 보유 순서로 모아 Q W E R D F 에 붙입니다(명령 패널 버튼과 같은 순서). WASD 는 이 키와 겹쳐 **카메라는 화살표 키**로 바뀌었습니다.
- 대상 없음이면 바로 보내고, 대상이 있으면 대상 고르기 모드: 커서에 범위 원, 좌클릭으로 지점·유닛(적/아군은 `Affects` 로), 우클릭·Esc 취소.
- 재사용 대기 중이면(고른 유닛 중 그 능력을 가진 유닛이 모두 대기) 버튼이 꺼지고 남은 초를 보여 줍니다. 서버 값 사이에는 로컬로 줄입니다.
- 연출(`AbilityEffects`): 직선 투사체는 정의의 속도로 날아가다 서버의 끝 이벤트에서 멈춤, 범위 예고는 지연 동안 붉은 원판, 발동은 주황(회복은 초록) 원판이 줄어들며 사라짐, 맞은 유닛은 번쩍.
- 상태 표시(`UnitViewManager`): 기절 = 머리 위 도는 노란 상자, 보호막 = 하늘색 고리, 둔화 = 몸이 푸르스름, 시전 중 = 코가 보라, 영웅 = 금색 관.

## 9. 지연 감추기

시전 명령은 누르는 순간 보내지만, 서버는 받은 뒤에야 선딜을 시작하고 클라이언트는 서버 이벤트를 보간 지연만큼 늦게 그립니다. 그대로 두면 왕복 지연과 보간 지연이 선딜 위에 더해져 "눌렀는데 반응이 없는" 시간이 생깁니다. 두 가지로 줄입니다.

### 9.1 즉시 표시 (클라이언트, `CastPrediction`)

판정은 바꾸지 않고 보여 주기만 앞당깁니다. 보내는 그 프레임에:

- 서버와 같은 규칙으로 시전할 유닛을 고릅니다(준비된 유닛, SingleCaster 면 대상에 가장 가까운 하나).
- 시전 자세(코 보라), 머리 위 시전 막대, 조준 표시를 보여 줍니다: 직선 투사체는 조준선, 지점 범위·돌진은 도착 원, 자기 주변 범위는 발밑 고리.
- 재사용 대기를 미리 걸어 버튼을 끕니다. 확인 전에 다시 눌러 시전이 처음부터 다시 시작되는 것을 막고, 서버 값이 올 때까지 예측 값을 지킵니다.

결과는 세 갈래입니다:

- **확인**: 서버의 시전 시작(CastStart)이 렌더 시각에 재생되면 예측을 내리고 서버 연출이 이어받습니다.
- **거부**: 서버는 거부한 시전 명령에 `CastCancel` 을 보냅니다. 클라이언트는 받은 즉시(렌더 시각을 기다리지 않고) 예측을 거두고 미리 건 재사용 대기를 풉니다.
- **유실**: 이벤트는 unreliable 이라 잃을 수 있습니다. 왕복 + 보간 지연 + 선딜 + 0.5초 안에 확인이 없으면 거둡니다.

사거리 밖이라 서버가 먼저 걸어가게 하는 시전(유닛 대상, 지점 범위)은 자세를 예측하지 않습니다. 걸어가는 동안 시전 자세가 보이면 틀린 연출이기 때문입니다.

### 9.2 선딜 지연 보상 (서버, 설정 `LagCompensation`, 기본 켬)

- **지연 측정**: 서버는 `받은 틱 − 명령의 ClientTick` 으로 명령 지연을 잽니다(`GameServer.CommandDelay`). ClientTick 은 클라이언트가 마지막 스냅샷 기준으로 추정한 서버 시각이라, 이 값은 편도보다 크고 왕복에 가깝습니다("플레이어가 본 화면 시각부터 서버가 받을 때까지"). 미래 틱이면 0, 1초를 넘으면 1초로 자릅니다.
- **선딜 단축**: 바로 선딜에 들어가는 시전이면 그만큼 선딜을 줄입니다. 상한은 `min(지연, 선딜 × 0.5, 0.1초)`(`AbilitySystem.WindupCredit`) 입니다. 조작한 클라이언트가 옛 ClientTick 을 보내도 선딜을 절반 넘게, 0.1초 넘게 줄일 수 없습니다.
- **보상하지 않는 경우**: 걸어간 뒤 시작하는 선딜(지연과 무관), AI 시전, 설정이 꺼져 있을 때.

### 9.3 측정 (`-autotest-cast on|off`, 실제 클라이언트, 영웅 Shock Bolt 4회 + 강제 거부 1회)

| 조건 | 보상 | 시전 자세 보임 | 서버 시전 시작 보임 | 투사체 보임 | 거부 예측 거둠 |
| --- | --- | --- | --- | --- | --- |
| 지연 0 | 켬 | 17ms (1프레임) | 167ms | 300ms | 84ms |
| 왕복 150ms | 끔 | 17ms | 306ms | 505ms | 250ms |
| 왕복 150ms | 켬 | 17ms | 300ms | **400~411ms** | 234~250ms |
| 왕복 300ms, 손실 10% | 끔 | 17ms | 504ms | 696ms | 367ms |
| 왕복 300ms, 손실 10% | 켬 | 17ms | 513ms | **621ms** | 400ms |

- 즉시 표시 전에는 누른 뒤 "서버 시전 시작 보임"까지(150ms 에서 약 0.3초) 화면 반응이 없었습니다. 지금은 다음 프레임에 보입니다.
- 보상은 투사체가 보이는 시점을 상한(0.1초)만큼 앞당깁니다. 300ms 행은 두 실행의 적응형 보간 지연(240 / 186ms)이 달라 차이가 75ms 로 나왔습니다.
- 위 표는 9.4(내 발사 즉시 재생)를 넣기 전 측정값입니다.

### 9.4 내 발사·예고는 받은 즉시 재생 (클라이언트, 기본 켬)

- **바로 재생하는 것**: 시전자가 **내 유닛**인 능력 이벤트 중 투사체 발사(ProjectileLaunch)와 범위 예고(AreaTelegraph). 렌더 시각을 기다리지 않습니다(`GameClient.PlaysImmediately`).
- **렌더 시각에 두는 것**: 다른 유닛과 얽힌 이벤트(적중·폭발·투사체 끝)는 그대로 렌더 시각에 재생합니다.
- **위치가 어긋나지 않는 이유**: 시전자는 선딜 동안 서 있으므로 화면 위치와 서버 위치가 거의 같습니다.
- **앞질러 지나가지 않게**: 바로 그린 투사체는 렌더 시각보다 앞서 날아가므로, 그대로 두면 적이 맞기(렌더 시각) 전에 적을 지나쳐 버립니다. 그래서 연출 투사체는 **화면에 보이는 맵 벽과 적(관통 수 반영)에서 멈추고** 서버의 끝 이벤트를 기다립니다(최대 0.6초). 판정은 여전히 서버가 합니다.
- **예고 원판**: 바로 그린 예고 원판은 폭발(렌더 시각)까지 남도록 보간 지연만큼 더 둡니다.
- **시전 자세**: 바로 재생한 직후 보간 지연 + 0.1초 동안은 스냅샷의 "시전 중" 플래그(과거 상태)를 무시합니다. 투사체가 나간 뒤에도 자세가 남지 않게 하려는 것이고, 즉시 표시 예측도 이 시점에 확인으로 칩니다.
- 명령줄 `-delayed-own-events` 로 끕니다(비교용).

`-autotest-cast on` (보상 켬), "투사체 보임" 은 실제로 그리기 시작한 시각:

| 왕복 지연 | 내 이벤트 렌더 시각 재생 | 내 이벤트 바로 재생 |
| --- | --- | --- |
| 0 | 300ms | **192ms** |
| 150ms | 414ms | **301~310ms** |
| 300ms, 손실 10% | 642ms | **462~467ms** |

선딜 보상 끔 + 바로 재생(150ms)은 397ms 였습니다. 결과적으로 150ms 환경에서 투사체가 보이는 시점이 505ms → 301ms 로 줄었고, 시전 자세는 처음부터 다음 프레임(17ms)에 보입니다.

## 10. 능력 추가하기

1. `AbilityId` 끝에 값 추가 → `AbilityCatalog` 정적 생성자에 정의 → 필요하면 `Loadouts` 에 보유 종류 추가.
2. 데이터로 안 되는 동작이면 `IAbilityScript` 구현 후 등록.
3. 새 전달 방식·상태가 필요하면 `AbilitySystem.Release` / `ApplyStatus` 와 `World.SpeedOf`(이동 영향) 확장.
4. `ProtocolVersion` 올리기(능력 ID 값이 프로토콜에 실림).
5. `AbilityTests` 에 동작 테스트(타이밍은 선딜·지연을 고려해 범위로), AI 가 쓰는지 확인하려면 `BattleBots_UseTheirAbilities` 의 목록에 추가.
6. 이 문서의 표 갱신.

남은 과제: 수치를 JSON 데이터로 분리, 마나 같은 자원 비용, 충전형, 쿨다운 감소, 플레이어 유닛 자동 시전, 원뿔·직사각 범위, 지속 피해(DoT), 능력 레벨업.
